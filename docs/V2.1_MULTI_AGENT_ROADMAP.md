## Context — why this work exists

PRO TRACK is an Electron + React (Vite) + Zustand + Firebase (Spark/free tier) study workspace. The owner asked for seven improvements after seeing a "day at a glance" timeline reference and hitting rough edges:

1. A real **day-at-a-glance** timeline that merges *everything* for a day, and a **working two-way Google Calendar sync** surfaced in the global ("All Scopes") view.
2. **Picture-in-Picture** that actually works: minimize to a small draggable floating rectangle with a live timer + pause, audio and countdown keep running, double-click restores the prior state without resetting anything.
3–4. **Optimize and inter-connect** the modules (habits, deep focus, notes, subjects, analytics, history, to-do, timetable) so you can jump between them effortlessly, they cooperate across modes/scopes, and things auto-tag.
5. **Input prompts** (check-ins, routines, quotes, anything needing an answer) take over screen-center with a **blur**, ask for input, then resume — with a visible "Esc / ✕ to close" hint and **snooze-if-unanswered**.
6. The **assistant voice** is robotic — make it natural.
7. **Every notification / toast / success chimes** for attention.

The surprising findings from exploration (already verified in code) shape the plan:

- **Google Calendar already exists** (`src/services/calendarService.js`): `calendar.events` scope, token capture, `listUpcomingEvents`/`pushSlotToCalendar`/`pullEventsToSlots`/`syncCalendar`, connect/disconnect UI, and a `/link-gcal` web handshake. **But** the OAuth token lives ~1h with a **mock** refresh token, sync is **manual**, push only covers **recurring weekly** slots, and the Netlify `gcal-sync.js` is a **501 stub**. → We harden + automate it ("live while open"), not build from zero.
- **PiP already mostly works**: the single Electron window *morphs* to a 240px always-on-top box (`ipcMain 'pip:enter'/'pip:exit'` in `electron/main.js`), rendering `src/components/focus/PipAppView.jsx` while the timer keeps ticking (`backgroundThrottling:false`). It needs **finishing**, not rebuilding. Two other PiP variants (`FloatingFocusPip.jsx`, `PipFocusWindow.jsx`) are dead on desktop.
- **`TodayAgenda.jsx` is already a vertical day timeline** → redesign + unified merge, not build-from-zero.
- **`pushIsland` (islandSlice) is the single notification funnel** but plays **no sound**; there is **no center-blur prompt** primitive yet; TTS is duplicated across 3 files with a robotic Web-Speech fallback; sounds are split across `lib/audioFX.js` + `lib/audioEngine.js` with **two different** localStorage flags.

**Locked product decisions (owner-confirmed):**
- GCal: **live while the app is open** — auto-sync on launch, on an interval, and after local edits while connected; a gentle "reconnect Google" prompt when the ~1h token lapses. No GIS silent-refresh, no server.
- GCal scope: **everything with a time** — recurring slots + one-time events + to-dos/tasks with due dates, both directions, including deletes.
- Center prompts: **only input-requiring prompts + quotes** go center-blur; informational toasts (deadlines, hydration, sync, success) stay in the Dynamic Island but now chime.

## GLOBAL RULES — every agent MUST obey these

These come from `claude.md` (repo blueprint) and the owner's coding rules. Breaking one is a failed phase.

**Architecture invariants**
1. **Zustand slices stay pure.** Slices return new objects and never run timers, I/O, audio, or side-effects. All side-effects live in hooks (`src/hooks/*`). (See `claude.md` §2, §6.)
2. **Immutability everywhere.** Never mutate state/props in place — spread into new objects/arrays.
3. **Focus ring math:** `phaseTotalSec` (focusSlice) is the *single source of truth* for ring progress. **Never** reintroduce `focusMin`/`customTimerSetting` into ring math (`FocusWidget`, `FocusMiniOverlay`, `FocusLockScreen`, `PipAppView`).
4. **YouTube embeds:** **NEVER add `&origin=`** to a focus-scene embed URL — the packaged app runs on `file://` and it breaks playback (regressed once in v1.6.0). See `src/lib/focusScenes.js`.
5. **Free-tier discipline** (`claude.md` §5): ephemeral/derived state stays local; **one bounded listener per active collection**, torn down on mode switch; coalesce writes (`arrayUnion`/`increment`/batch); bound history reads with `limit`; **no dependency on Cloud Functions or any server** (Spark plan).
6. **Lucide icons:** import **by name** (`import { Play } from 'lucide-react'`) — never `import * as`, it balloons the bundle.
7. **File size / cohesion:** keep new files 200–400 lines (800 max); many small feature-scoped files over few large ones; one service module per domain.
8. **No secrets in code.** API keys come from `secureStorage`/settings, never hardcoded.
9. **Encrypted fields:** `todos.text`, `todos.notes`, and note content are AES-GCM encrypted at rest (`cryptoService`). Read/write them only through the existing services; never log plaintext.
10. **No `console.log` in shipped code paths** (use existing `console.warn/error` only for genuine error branches, matching surrounding style).

**Build gates (run before you call a phase done — ALL must be green):**
```bash
npm run lint
npm test
npm run build
# Electron main+preload build:
# (Windows PowerShell) $env:ELECTRON="true"; npx vite build
```
- `npm test` is Vitest (95+ unit tests). Any pure logic you add needs a test in `src/lib/__tests__/` or `src/hooks/__tests__/`. Use `vi.useFakeTimers()` for anything reading `new Date()`.

**Isolation rules (prevent cross-agent merge conflicts):**
- Work on your phase's **own branch** off `development` (e.g. `feat/p3-pip`). Never commit to `master`.
- Edit **only** files in your phase's **"Files you OWN"** list. If you must touch a **shared hotspot** file (listed per phase), make **additive, anchored** edits only — do not reformat or move unrelated code.
- **Shared hotspot files** (multiple phases touch them → edit surgically, never wholesale): `src/components/layout/Dashboard.jsx` (mounts hooks/overlays), `src/components/settings/SettingsPanel.jsx`, `src/components/common/ZenOverlay.jsx`, `src/components/widgets/TimetableWidget.jsx`, `claude.md`.
- Do **not** delete another phase's code. If something looks dead, confirm it's yours before removing.
- Commit messages: conventional commits (`feat:`, `fix:`, `refactor:`…). End every commit body with:
  `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`

- Two flags (`protrack:sounds` vs `protrack:sounds_enabled`) drift out of sync.

**Files you OWN:**
- CREATE `src/lib/sound.js`
- CREATE `src/lib/__tests__/sound.test.js`
- EDIT `src/lib/audioFX.js` (turn into thin re-exports — see steps)

**Files you must NOT touch:** `audioEngine.js` (leave the focus chime + `MultiTrackMixer` exactly as-is), any consumer/widget, `useIslandCycle.js` (that's P5), `SettingsPanel.jsx`.

**Steps:**
1. In `src/lib/sound.js`:
   - Move the four WebAudio synth bodies from `audioFX.js` into `sound.js` unchanged (chime/pop/success/habit). Add two more: `playNotify()` (soft two-tone) and `playError()` (low descending tone) and `playPrompt()` (gentle rising tone for center prompts).
   - Export `soundsEnabled()` / `setSoundsEnabled(bool)` reading the **single** canonical key `protrack:sounds`. Include a **one-time migration**: if `protrack:sounds` is unset and `protrack:sounds_enabled === 'false'`, set `protrack:sounds='false'`.

2. In `src/lib/audioFX.js`: replace the synth implementations with re-exports from `sound.js` (`export { playChime, playPop, playSuccess, playHabitChime } from './sound'`). This keeps all existing importers working with zero changes.
3. Test (`sound.test.js`): flag migration logic; `chimeForIslandKind` mapping table; `playSound` is a no-op when disabled (mock `AudioContext`).

**Invariants:** pure module + try/catch around every WebAudio call; do not change `audioEngine.playChime` (focus completion keeps its current sound); do not wire any UI.

**Done when:** build gates green; existing sound callers unaffected; `sound.js` exports the full bank + `chimeForIslandKind`.

## Phase P2 — Google Calendar two-way live sync (#1 sync)

**Branch:** `feat/p2-gcal` · **Depends on:** P1 merged (shares `TimetableWidget`) · **Size:** L

**Goal:** Make the *existing* Google Calendar integration feel automatic and bidirectional for **everything with a time**, while the app is open, on the free tier. Surface it in the global scope + Settings.

**How it works today (context — read `src/services/calendarService.js` first):**
- Token: Firebase Google popup (web) or a desktop→browser handshake via `users/{uid}/gcal/handshake` → stored in `secureStorage['protrack:auth_core']` as `{access_token, expires_at, refresh_token:'mock_gcal_refresh_token'}`. **No real refresh.** On 401, `calFetch` clears the token; `calFetchWithRetry` currently calls `connectCalendar()` again (which on desktop *re-opens the browser* — undesirable auto-loop; you will change this to a reconnect prompt).
- Direct Calendar v3 API: `listUpcomingEvents`, `pushSlotToCalendar` (recurring weekly RRULE only), `pullEventsToSlots` (timed events → slots; skips all-day), `syncCalendar` (pull then push local-only slots). Every method first tries Netlify `/.netlify/functions/gcal-sync` which is a **501 stub** → always falls through to direct API.
- Consumers: `TimetableWidget.jsx` (connect/synced button + "From Google" list), `SlotEditorModal.jsx` (`pushSlotToCalendar` stores `googleEventId`), `SettingsPanel.jsx` (connect/unlink).

**Files you OWN:**
- EDIT `src/services/calendarService.js` (major)
- CREATE `src/hooks/useCalendarSync.js`
- CREATE `src/lib/gcalMap.js` (pure event↔item mapping) + `src/lib/__tests__/gcalMap.test.js`
- EDIT (surgical, hotspots) `src/components/settings/SettingsPanel.jsx` (GCal section: last-sync, Sync now, inbox-mode picker, auto-sync toggle), `src/components/layout/Dashboard.jsx` (mount `useCalendarSync`), `src/components/widgets/TimetableWidget.jsx` (sync status/button only)
- EDIT `claude.md` (document: `gcal/handshake`, `settings.gcalInboxModeId`, `settings.gcalAutoSync`, `googleEventId` now stored on todos/tasks too)

**Files you must NOT touch:** `TodayAgenda.jsx`/`dayAgenda.js` (P1), `timetableService`/`todoService`/`subjectService` public signatures (call them; don't rewrite), auth/login flows in `AuthContext`/`firebase.js`.

**Steps:**
1. **Stop the silent re-consent loop:** change `calFetchWithRetry` so a 401/"expired" does **not** call `connectCalendar()`. Instead throw a typed `CalendarAuthError`; the hook (step 4) surfaces a reconnect prompt.
2. **Drop the dead Netlify calls:** remove the `callSyncFunction('sync_up'/'sync_down')` attempts (they always 501) — call the direct API straight. Leave `netlify/functions/gcal-sync.js` file in place but unused (or delete if nothing else references it — verify).
3. `src/lib/gcalMap.js` (pure, tested):
   - `eventToItem(gcalEvent)` → `{ kind:'slot'|'todo', ...fields }`: timed recurring → slot (existing logic, moved here); timed one-off → a todo `type:'event'` with `eventDate/eventStartMin/eventEndMin`; all-day with a date → todo with `dueAt`. Carry `googleEventId`, `source:'gcal'`, `updated`.
   - `itemToEvent(item)` for the reverse: slot → recurring weekly (existing), one-time event → single dateTime event, todo/task with `dueAt` → timed or all-day event. Reuse `nextOccurrence` (`lib/time.js`).
   - `mergeStrategy(localUpdated, remoteUpdated)` → last-write-wins.
4. `calendarService.js` — add `syncEverything(uid, { modes, inboxModeId, slots, events, todos, tasks })`:
   - **Pull (delta):** persist a `syncToken` per calendar in `secureStorage`; call events.list with `syncToken` when present else `timeMin`; on `410 GONE` clear token → full resync. For each changed event map via `eventToItem`; `status:'cancelled'` → **delete** the mapped local item (delete propagation). New/updated GCal items land in the **inbox mode** (`settings.gcalInboxModeId`, default `activeModeId` or `modes[0].id`). Dedupe by `googleEventId`.
   - **Push:** for every local item that has a time and no `googleEventId`, create the event and write `googleEventId` back (slots via `updateSlot`, todos via `todoService.updateTodo`, tasks via `subjectService.updateTask`). For items that changed since last push (compare `updated`), PATCH.
   - **Delete reconciliation:** items carrying a `googleEventId` that no longer exist locally → delete their GCal event. (Bounded: only over items already loaded.)
   - Coalesce Firestore writes (batch where the service supports it); keep reads bounded.
5. `src/hooks/useCalendarSync.js` (mounted once in Dashboard; runs on web + desktop):
   - If `isCalendarConnected()` and `settings.gcalAutoSync !== false`: run `syncEverything` on mount, then on `setInterval` (default 5 min), on `window` `focus`, and after local mutations (debounced ~4s via a `calendarDirty` counter in `uiSlice`, bumped by the widgets that already write slots/todos/tasks — or simplest: interval + focus only for v1, note the debounce as a follow-up).
   - Push a sticky Island `kind:'sync-online'` "Calendar synced" briefly on success; on `CalendarAuthError` push a sticky `kind:'sync-offline'` "Reconnect Google Calendar" whose tap calls `connectCalendar()` (single, user-initiated — never auto).
   - **Never** run during a running/locked focus session block? (Not required — sync is background and silent; just avoid noisy Island spam: only toast on state change, not every tick.)
6. `SettingsPanel.jsx` GCal section: show connected state + **last sync time**, a **Sync now** button, an **inbox-mode** dropdown (`settings.gcalInboxModeId`), and an **Auto-sync** toggle (`settings.gcalAutoSync`). Persist via existing `userService.updateSettings`.
7. Update `claude.md` data-model + flows.

**Invariants:** **no Cloud Functions / server** (all client-side direct API); token only in `secureStorage`; **do not** request `calendar.events` at base login (keep on-demand consent); **do not** add `&origin=`; bounded reads; the reconnect prompt is the only re-auth path (no silent browser re-open). Conflict policy = last-write-wins by `updated` (documented).

**Known limitation to state in the PR:** because the token can't refresh in the background on the free tier, sync is "live while the app is open" and will ask the user to reconnect roughly hourly. This is by design (owner-approved).

**Done when:** build gates green; connecting Google then editing on either side reflects on the other while the app is open; deletes propagate; global "All Scopes" day/week views show Google items; Settings shows last-sync + controls; `gcalMap.test.js` passes.
